Storage Engine & ext4 Architecture Cheat Sheet

Quick-reference specs, ext4 limits, hashing formulas, and POSIX impedance rules.

1. Mechanical ext4 Limits & Sizing Constants

Metric ext4 Value Operational Implication
Block Size 4,096 bytes (4 KB) Standard disk allocation and directory block unit.
Directory Entry Size 72 bytes 8-byte header (ext4_dir_entry_2) + 64-byte SHA-256 hex filename.
Max Entries / 4KB Block 56 entries $\lfloor (4096 - 12) / 72 \rfloor = 56$. Under 56 entries = fits in 1 block, zero HTree splitting.
HTree Hash Width 32-bit hash Birthday paradox collision threshold: $\sqrt{2^{32}} \approx 65,536$ entries.
Max Subdirectories EXT4_LINK_MAX = 65,000 Subdirectory count per parent directory before dir_nlink clamps to 1.
Directory Deallocation NEVER shrinks Unlinking files leaves allocated directory blocks intact. Manual fix: e2fsck -D.

2. Hashed Key Addressing Specification

Deterministic Addressing Formula
hash = hex_lower(SHA-256(key.getBytes(StandardCharsets.UTF_8)))
Component Format / Value Rationale
Charset UTF-8 Uniform byte encoding across all OS/JVM platforms regardless of system default.
Hash Function SHA-256 $2^{256}$ space ($5.8 \times 10^{-47}$ collision risk at 10B items/day for 1,000 yrs); avalanche bit spread.
Encoding Lowercase Hex ([0-9a-f]{64}) Case-sensitivity safety across Linux ext4, macOS APFS, and Windows NTFS.
Security CWE-22 Immunity Guarantees no ../, slashes, null bytes (\0), or control characters in payload filenames.

4. S3 vs POSIX Impedance & Metadata Decoupling

Aspect Amazon S3 Semantics POSIX / ext4 Filesystem ADR 0001 Resolution
Namespace Flat string keys (opaque UTF-8 up to 1024B). Hierarchical tree of directory nodes and files. Hash keys to flat 64-char IDs across uniform 2-tier tree.
File vs Dir photos and photos/pic.png can coexist. A path node cannot be both a file and directory. Decoupled: payloads are only at leaf depth 3.
MIME Types Supplied via HTTP Content-Type header. Inferred from extensions (.png) or file headers. Decoupled: stored in SQLite/H2; disk payload has no extension.
Atomic Writes PUT is atomic last-write-wins. Direct writes expose partial data during crashes. Stream to staging/{uuid}.tmp, then atomic POSIX rename().

5. Directory Blocks vs. Data Blocks & Two Hashing Layers

Concept Directory Block Data Payload Block
What it contains Array of directory entries (72 bytes: 8-byte header + 64-char filename). Raw bytes of the object payload (image, video, document).
Size impact Always 72 bytes per file entry, regardless of file size. Grows in 4KB block multiples depending on payload size.
Hashing applied ext4 32-bit HTree hash of filename (collides at ~65,536 entries). Application-level 256-bit SHA-256 of S3 key ($5.8 \times 10^{-47}$ collision risk).
